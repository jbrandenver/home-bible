### Client fixes (each has a commit message with full reasoning)
- **Profile write failed on every sign-in** since 033. **No upsert can work on
  `profiles`** — PostgREST compiles `.upsert()` into
  `ON CONFLICT (id) DO UPDATE SET id = excluded.id, …`, and `id`/`email`/
  `created_at` have no UPDATE grant. Now UPDATE-then-INSERT.
- **Unresolved session read as "signed out"** → reads ran as `anon` → hard
  errors (031/033 revoked anon's grants). `guardedRead` retries once after an
  uncached session check and never leaks Postgres text.
- **Twelve `get*DataContext()` resolvers** decided demo-vs-account from the
  5-second `getCurrentUser()` cache. A stale `null` = demo mode = **the next
  save goes to localStorage**. Silent data loss, no error possible. All twelve
  now fall back to `getCurrentUserUncached()`.
- **`add-rooms` rendered its form in every `dataMode`**, so non-account modes
  fell through to `saveRooms()` (localStorage) then `resetForm()` — a cleared
  form that looked like a save.
- **Customer-facing errors rewritten** (`describeDataError`), 15 tests. An
  **allowlist**, not a blocklist — a test caught the blocklist version passing
  `ERROR 0x1f unexpected driver failure` to a customer.
- **Write controls hidden from viewers** (`usePropertyAccess`, `ViewOnlyNotice`).
  **Fails OPEN** — it is a courtesy, not a security control; RLS enforces.
  Layout carries the notice on every page; per-page button hiding done for 10.
- **Demo import** required an existing property, so it was unusable for a fresh
  signup. Now creates the home from the demo copy; `/welcome` opens on
  import-or-discard.
- **Invitations**: pending ones now appear on the dashboard (no link needed);
  refusal messages name the real cause.
- **Property switcher** shows from the first home, marks "· shared with me",
  carries "+ Add a home of my own".

## Gotchas worth not rediscovering

- **`supabase db push` is unsafe here** (001_ naming vs timestamp ledger). Use
  `supabase db query --linked -f <file>` then insert the
  `supabase_migrations.schema_migrations` row by hand. Always dry-run in a
  `begin; … rollback;` with a `raise exception` carrying the result.
- **Workers Builds deploys the Next app but NOT edge functions.**
  `supabase functions deploy <name>` is a separate required step.
- **`next build` runs ESLint**; build locally before pushing. Don't build while
  the dev server runs (`rm -rf apps/web/.next` first).
- **`digest_log` is UNIQUE on (user_id, kind, period_key)** — retries must
  upsert, not insert.
- **`getCurrentUser()` is fine for rendering, never for deciding where data is
  written.** Use `getCurrentUserUncached()` for that.
- The embedded browser stalls in Supabase's auth client — signed-in paths can't
  be verified there. Verify at the data layer, or have Jesse click it.
- **Don't ask Jesse to paste an `Authorization: Bearer` header** — ask yes/no.
  He pasted a live JWT once already.

## Verification habits that worked

- Reproduce as `set local role authenticated` / `anon` in a rolled-back txn —
  `anon` reproduces "permission denied for table X" exactly.
- `get_logs(service='postgres')` for the error; note ~10 min ingestion lag.
- Confirm writes landed by timing: a batch import writes rows milliseconds
  apart, a human clicking a wizard does not.
